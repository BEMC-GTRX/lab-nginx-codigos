¡Funciona! Laboratorio de códigos de estado HTTP

Si ves esta página, tu servidor nginx está funcionando y te ha respondido con el código 200 OK. Este sitio solo existe en tu equipo (localhost) y sirve para practicar con el comando curl desde la terminal.

1. ¿Qué es un código de estado?

Cada vez que pides algo a un servidor web, este te responde con un número de 3 cifras que resume qué pasó con tu petición. El primer dígito indica la "familia":

FamiliaSignificadoEjemplo
1xxInformación: "sigo procesando"100 Continue
2xxÉxito: "todo bien"200 OK, 206 Partial Content
3xxRedirección: "lo que buscas está en otro sitio"301 Moved Permanently, 304 Not Modified
4xxError del cliente: "tu petición tiene un problema"400, 403, 404, 405, 416
5xxError del servidor: "el problema es mío"500, 502, 503

2. Las opciones de curl que vamos a usar

OpciónQué hace
-IPide solo las cabeceras (petición HEAD). La primera línea muestra el código.
-iMuestra las cabeceras y el contenido.
-vModo detallado: ves lo que envías (>) y lo que recibes (<).
-LSigue las redirecciones (3xx) automáticamente.
-X MÉTODOCambia el método HTTP (GET, POST, PUT, DELETE...).
-H "Cabecera: valor"Añade o cambia una cabecera de la petición.
-s -o /dev/null -w "%{http_code}\n"Modo silencioso, tira el contenido y muestra solo el código.

3. Ejercicios

Consejo: ejecuta cada comando, mira la primera línea de la respuesta (por ejemplo HTTP/1.1 404 Not Found) e intenta explicar por qué el servidor respondió eso.

Ejercicio 1 — 200 OK

Pedimos esta misma página. Existe y nginx puede leerla.

curl -I http://localhost:8080/

Ejercicio 2 — 404 Not Found

Pedimos un archivo que no existe.

curl -I http://localhost:8080/no-existe.html

Ejercicio 3 — 301 Moved Permanently

Pedimos una carpeta sin la barra final. nginx nos redirige a /carpeta/. Busca la cabecera Location: indica a dónde nos manda.

curl -I http://localhost:8080/carpeta
curl -IL http://localhost:8080/carpeta     # con -L curl sigue la redirección

Ejercicio 4 — 403 Forbidden (carpeta sin index)

La carpeta existe, pero no tiene index.html y nginx tiene prohibido listar su contenido.

curl -I http://localhost:8080/privado/

Ejercicio 5 — 403 Forbidden (permisos de Linux)

El archivo existe, pero sus permisos no dejan leerlo al usuario de nginx (www-data). Compáralo con ls -l /var/www/html/secreto.txt.

curl -I http://localhost:8080/secreto.txt

Ejercicio 6 — 405 Not Allowed

Intentamos enviar datos (POST) a una página estática. nginx no sabe qué hacer con ellos.

curl -i -X POST http://localhost:8080/

Ejercicio 7 — 206 Partial Content

Pedimos solo los primeros 100 bytes de la página (así funcionan las descargas que se pueden pausar).

curl -i -r 0-99 http://localhost:8080/

Ejercicio 8 — 416 Range Not Satisfiable

Pedimos un trozo que está más allá del final del archivo.

curl -I -r 999999- http://localhost:8080/

Ejercicio 9 — 304 Not Modified

Primero descargamos la página guardando su fecha original (-R). Después preguntamos "¿ha cambiado desde esa fecha?" (-z). Como no ha cambiado, el servidor no la vuelve a enviar. Así ahorran datos los navegadores con su caché.

curl -s -R -o copia.html http://localhost:8080/
curl -I -z copia.html http://localhost:8080/

Ejercicio 10 — 400 Bad Request

Enviamos una petición mal formada: HTTP/1.1 exige la cabecera Host y la mandamos vacía.

curl -I -H "Host:" http://localhost:8080/

Reto final — solo el código

Comprueba todas las rutas de golpe mostrando únicamente el número:

for ruta in / /no-existe.html /carpeta /privado/ /secreto.txt; do
  echo "$ruta -> $(curl -s -o /dev/null -w '%{http_code}' http://localhost:8080$ruta)"
done

4. ¿Y los 5xx?

Los errores 5xx aparecen cuando el servidor falla o cuando nginx reenvía la petición a otra aplicación que no responde (por ejemplo, 502 Bad Gateway). Para provocarlos hace falta configuración extra, así que los veremos más adelante.

Prueba esto: para nginx con sudo systemctl stop nginx y ejecuta curl -I http://localhost:8080/. ¿Recibes un código? (Pista: si no hay servidor, no hay nadie que responda.) Vuelve a arrancarlo con sudo systemctl start nginx.
